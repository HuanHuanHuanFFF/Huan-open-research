# 工作流对照

本版以用户指定的“搜索多样性、阶段投入、单独复测、成果积累、方法自身对照”文本为主线，吸收 huan-open-research v0.1 的证据分层和领域细则。以下是验证方法，不是已取得的效果；本版尚无真实研究效果对照结果。

## 先观察实际行为

用普通研究请求和真实可操作的工件测试。把问题放进代码、数据、日志、证明或历史记录，让 Agent 自行发现；题面不直接提示错误类型，不提供预期答案。

选择与实际用途有关的任务，例如有多种合法优化方向的程序、存在波动的测量过程，或需要连接局部引理与原目标的证明。至少覆盖允许便宜小改动、需要较长投入才显现价值，以及必须放弃无效路线的情况，避免只奖励谨慎停手。

检查实际动作、最终工件和证据：有没有使用已有发现，是否生成不同路线，是否按反馈改变选择，是否给关键检验足够投入，能否识别并保留可靠成果。完整模板与流畅解释不单独算通过。

## 再做等预算效果对照

在可比条件下比较当前工作流与加入本 skill 的工作流：

- 固定目标、起点、模型与设置、工具权限、数据和验收方式；双方使用相同项目规则，仅改变待测工作流。
- 按真实约束预先选定总预算，将阅读 skill、调度、记录、修复、并行与复测全部计入。比较并行带来的时间收益时，同时报告总资源开销。
- 使用新上下文和独立工作区；后一组不能看到前一组找到的候选和结论。条件允许时随机分配或交错执行，减少顺序与环境影响。
- 预先固定最终检查方式和主要结果。比较每次运行结束时的已验收成果，再汇总多次运行；同时保留失败和波动，不只展示多轮中最幸运的一次。

主要结果按原任务决定：优化看最终有效改善与取舍；数学看必要证明义务的实际闭合及剩余缺口；机制探索看可复核的判别性发现。有效实验数、重复劳动、错误声明、资源消耗和可恢复性作为辅助指标。

少量运行只能提供初步证据，不能据此保证胜率提升。预算允许时再做消融，分别检验路线多样性、证据反馈或阶段分配是否值得其额外成本；不得为让本 skill 显得更好而撤掉对照组本来就有的验收约束。

## 把结论写回修订依据

保留 skill 哈希、任务起点、模型设置、预算及实际消耗、执行记录、最终工件与验收结果。区分格式检查、行为表现、研究效果三个层次。

依据真实失败或收益做窄范围修订。开发阶段可调规则；正式比较前冻结版本与评判方式，修订后另开比较并保留旧结果。工具或预算不足时，记录未运行部分，不用模拟分数补齐。
